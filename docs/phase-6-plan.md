# 第六阶段规划：答辩部署验证、观测闭环与受限扩展实验

## 进入条件

第五阶段的 API/Web 自动回归、受控诊断案例和降级边界已验收；active XGBoost、shadow TCN、知识库和解释制品均保持版本可追溯。第六阶段只在脱敏的 3W 回放与课程演示环境内开展，不接入现场井控或生产数据。

## 目标

把已经封版的本地可复现系统转化为可答辩的部署证据，并以严格受限的方式完成“7 变量通用模型与扩展变量/真实数据模型”的对照实验。重点是可靠性、可观测性和报告证据，不增加新的自动控制能力。

## 执行基线与发布门禁

- 本阶段起点固定为已通过第五阶段诊断验收的 Git 提交。每次部署都必须记录完整 commit、镜像 ID/摘要、Compose 配置摘要以及 active、shadow、解释制品和知识库 manifest 的版本；仅有 `latest` 标签不构成可追溯部署证据。
- 部署前先在本地执行 API、ML 和 Web 回归、`git diff --check`、敏感文件审计和镜像构建；部署后依次核对容器健康、`/api/health`、`/api/models`、反向代理和 Web 页面。任一门禁失败时停止后续演示，先回退到上一份已验证版本。
- 所有现场采集证据、性能原始记录和截图保存到 Git 忽略的 `docs/.local/phase-6/`，按 `release/`、`replays/`、`faults/`、`experiments/`、`defense/` 分目录归档。可提交的文档只记录脱敏摘要、哈希、版本和结论。
- 本阶段仍只允许受控 3W 回放；不增加 MQTT 控制命令、不扩大 API 数据范围、不把真实生产遥测、凭据、完整模型或原始 Parquet 放入仓库。

## 工作包

1. **发布可追溯性、ECS/Pi 部署验收与运行证据**
   - 按 `infra/README.md` 在 ECS 部署已验证的主分支镜像，确认 Nginx、API、PostgreSQL、Mosquitto 和 Web 的健康状态、内存上限与只读模型挂载。
   - 将 Git commit 作为镜像 OCI label 或写入不含秘密的部署 manifest；记录部署前后容器 image ID、创建时间、健康检查结果和回退目标。ECS 缺少 Git 工作树时，必须通过该 manifest 而不是目录时间判断版本。
   - 从 Pi 经现有 WireGuard 私网回放一个 Normal 和三个目标异常实例，验证 TLS、ACL、心跳、10×/20× 回放、WebSocket、active 告警与 shadow 对照。
   - 对 Pi 记录 edge-agent 镜像摘要、配置 schema 版本、数据 instance 哈希和最后心跳；验证重启后不自动恢复到未知实例、命令序列可审计且不改变安全边界。
   - 形成脱敏部署核验单：镜像摘要、Git commit、模型/知识库/解释制品版本、服务健康结果和截图；不提交地址、证书或凭据。

2. **轻量运行观测与故障演练**
   - 为 API 增加只读、无敏感信息的运行摘要：模型可用性、窗口预热状态、最近推理延迟和诊断证据状态的聚合计数；避免暴露遥测内容、连接信息或内部路径。
   - 在演示环境演练 MQTT 不可达、Pi 心跳中断、shadow 制品不可用、解释制品缺失和知识库条目被撤回。记录触发方式、发现时间、恢复步骤、可见降级状态及 active 报警连续性。
   - 为每种演练定义明确通过条件：active 不可用时禁止伪造预测；shadow 不可用时 active 连续；解释缺失时只能 `degraded`；知识条目撤回时只能 `refused`；MQTT 断开后不得积压失控重发或发布控制命令。
   - 设定课程演示的容量边界（单 worker、2 GiB ECS、最大历史查询范围）并记录空闲和回放期间 CPU/内存、API p50/p95、WebSocket 到达延迟、MQTT 接收至推理完成延迟及数据库增长量。
   - 为日志与证据规定最小保留策略：服务健康、模型切换/不可用、诊断降级和异常恢复事件必须带 UTC 时间、关联版本和请求/窗口标识；日志不得包含完整遥测、凭据或公网地址。

3. **扩展变量与真实数据泛化对照**
   - 在 Mac 离线构建 27 变量可用性 manifest；严格按 instance/well 复用已有 split 原则，缺失变量的实例不得静默填充或跨集移动。
   - 在训练前固定实验问题、特征协议、目标类别、排除规则、超参数搜索预算、随机种子和主指标；将各域（真实、模拟、hand-drawn）与变量覆盖率分开报告，避免以总体 Accuracy 掩盖域偏移。
   - 以相同目标类别和指标比较 7 变量通用模型、27 变量候选模型，以及真实数据测试子集。报告 Accuracy、Macro F1、每类 Recall、混淆矩阵、CPU 单窗口延迟、制品大小、训练耗时和数据覆盖率。
   - 增加稳健性实验：对 7 变量模型做单变量缺失拒绝、短时缺失、噪声扰动和窗口长度敏感性检查；对 27 变量候选模型报告因严格缺失契约被排除的实例比例。所有试验只生成离线结果，不把填补策略带入 active 推理。
   - 候选模型仅以离线实验或 `shadow` 方式展示；是否替换 active XGBoost 必须由人工评审并由项目负责人明确批准，默认不升级。

4. **答辩材料与最终交付检查**
   - 准备 8–10 分钟演示路径：系统问题、架构与边云边界、真实回放、active/shadow 对照、可解释诊断与拒答、降级/回退、实验指标和局限性。
   - 将演示拆为“主路径（4–5 分钟）+ 故障/回退路径（2 分钟）+ 指标与局限性（2–3 分钟）”，为每页准备预期状态、证据编号、口述要点和不能演示时的截图备份；截图只用于展示，不替代实时健康检查。
   - 整理数据卡、模型卡、知识库治理表、阶段验收记录、部署 manifest、实验登记表和风险说明，确保结论可由提交的代码、无秘密文档和本地制品重现。
   - 开展一次独立的答辩彩排：由非实施者按 runbook 执行部署核验、四类回放、一次降级和一次回退；记录卡点并完成修复后复测。
   - 最终执行 API/ML/Web 回归、镜像构建、依赖与敏感文件审计，并将可部署版本打上课程答辩标签；标签、部署 manifest、演示记录和提交必须相互引用。

5. **任务编排与阶段节奏**
   - 先完成发布门禁和基线部署核验，再并行推进运行观测/故障演练与离线扩展变量实验；只有前两者有可复核结果后才编排彩排，避免将排错留到答辩当天。
   - 每个工作包维护“负责人、输入版本、开始/完成时间、证据位置、通过条件、阻塞项、回退版本”七项登记。任何未通过项进入明确的修复任务，不以口头结论关闭。
   - 建议按三个冲刺执行：冲刺 A（版本可追溯、部署和四类回放）、冲刺 B（观测、五类故障与泛化实验）、冲刺 C（独立彩排、修复、冻结）。每个冲刺结束执行一次回归和证据完整性检查。

## 验收标准

- ECS 与 Pi 演示链路可从受控启动步骤复现；TLS/ACL 生效，服务在资源限制内稳定运行，且主动模型报警与 shadow 结果始终隔离。
- 至少四类回放、五种降级/故障情形均有脱敏记录；所有恢复过程不引入控制命令，也不让诊断影响 `Alarm`/`AlarmState`。
- 7 变量与扩展变量实验使用可追溯、无泄漏的同类评估协议；结果按数据域、变量覆盖率和稳健性场景明确标注局限性，候选模型未被自动升级为 active。
- 任意一次部署均可由 commit、镜像摘要和部署 manifest 三者交叉定位；部署后的健康、模型加载、Web 和反向代理检查均有记录，并能回退到上一已验证版本。
- 答辩材料、演示手册、数据/模型/知识库版本和 Git 标签互相可追溯；仓库不包含原始数据、模型制品、私钥、密码、地址或令牌。

## 默认决策与退出条件

- 默认维持 XGBoost `active`、TCN `shadow`；第六阶段不启用 LLM 自由生成或现场控制。
- 如 ECS 资源、网络、制品或候选实验不满足验收，只保留已通过第五阶段的受控诊断能力并在答辩中说明边界，不以降低安全边界换取功能展示。
- 当部署验收、对照实验和答辩材料均完成后，项目进入最终答辩冻结阶段；后续变更仅限经复核的修复。
