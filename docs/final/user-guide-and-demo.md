# OilWell AI 系统使用说明与课程演示方法

适用课程：本科《石化信息工程》结课作业。

项目定位：边云协同油井监测与知识增强辅助分析教学系统。

文档整理：2026 年 10 月 18 日。

适用版本：`main` 课程交付版，已收齐基础提交 `359f10a` 与 DeepSeek 接入适配；精确版本以 `main` 提交为准。

说明依据：2026-09-22 的生产部署、回放与真实 LLM 诊断验收，以及 2026-10-17 的本地测试和只读复查。2026-10-18 仅精简本地交付内容，不连接生产或树莓派；后续运行状态以页面和服务检查为准。

已验收的演示内容：七变量监测、XGBoost/TCN 同窗口对照、报警与历史查询，以及 DeepSeek V4.1 Flash 辅助分析。已保存的报告 31 可直接用于展示，定位方法见第 4.5 节；查看已有报告不产生新的模型调用。

## 1. 系统能做什么

系统用 Petrobras 3W 油井数据回放模拟现场边缘采集。树莓派发送压力、温度、流量相关数据，云端保存数据并运行模型，网页展示曲线、模型结果、报警与可追溯的辅助分析。

数据路径：

```text
3W Parquet 文件 → 树莓派 Edge Agent → MQTT/TLS → 云端 FastAPI
                                                    ├→ PostgreSQL 历史记录
                                                    ├→ XGBoost active / TCN shadow
                                                    └→ WebSocket → 浏览器实时监测
模型结果 + 窗口统计 + 报警摘要 + 检索引用元数据 → DeepSeek 辅助分析
受审阅知识条目 → 系统生成引用；LLM 不可用 → 受约束模板
```

系统控制的是教学数据回放，不是油井设备。模型和诊断结果用于教学与人工辅助分析，不能作为现场控制指令。

## 2. 打开系统与演示前准备

演示入口：<https://oil-well-ai-demo.dowdah.com/>。

日常使用只需浏览器；答辩前确认电脑能访问网站，树莓派已通电且私网链路正常。使用部署完成后的页面，若页面仍显示旧文案，重新加载或关闭旧标签页后重新打开。

2026-10-17 复查时设备在线，但速度为 20×、未加载实例；四个样例文件仍可选。演示前要先加载文件并应用所需速度，不能假设上次的实例与速度一直保留。

### 2.1 五分钟检查

1. 打开“总览”，确认油井列表可用、在线设备数不为零。
2. 打开“边缘与回放”，确认 `edge-pi-01` 的心跳时间持续更新，且状态不是 `OFFLINE`。
3. 打开“模型中心”，确认 active XGBoost 和 shadow TCN 均显示 `ready`。
4. 按第 3 节启动回放，确认设备执行回执、实时曲线和新的完整推理窗口。
5. 在“辅助诊断”先查看已保存的报告 31，检查窗口、引用和降级原因。若要验收当次回放的新窗口，再生成一次新报告；该操作会发送统计摘要到 DeepSeek，并可能产生 API 费用。
6. 准备演示录像、截图及架构图作为备用。使用备用材料时明确说明是已录制或历史结果。

不要将“设备在线”“WebSocket 已连接”或健康接口返回正常单独视为全链路通过。实时演示应同时看到新遥测和新推理结果。

### 2.2 三种时间不要混淆

| 时间 | 含义 | 使用位置 |
| --- | --- | --- |
| 原始采样时间 | 3W 文件中的时间，可能为 2016、2017 年 | 曲线、模型窗口、历史时间筛选 |
| 接收及操作时间 | 今天实际进行回放或执行操作的时间 | 心跳、命令回执、部分审计记录 |
| 浏览器显示时间 | 浏览器按本地时区转换后的时间 | 多数表格和日期输入框 |

回放没有把历史数据改成今天的采样时间。历史查询不要直接填写今天；先不填时间查询，再按实际记录缩小范围。带 `Z` 的时间是 UTC，中国标准时间比 UTC 快 8 小时。辅助诊断页的记录创建时间直接显示 UTC 字符串，例如 `2026-09-22T09:28:31.184659Z` 对应北京时间 17:28:31。

## 3. 边缘设备与数据回放

入口：左侧“边缘与回放”。

### 3.1 选择一个实例

1. 如果设备显示 `REPLAYING` 或 `PAUSED`，先点击“停止”。
2. 等待页面提示设备“已执行 STOP”。“已发送”只表示命令已提交，尚不能认定设备执行成功。
3. 在“教学实例”下拉框选择一个已挂载的文件，点击“加载实例”。
4. 等待设备执行确认，再核对卡片上的“回放实例”。
5. 在“回放速度”中选择 `10×`，点击“应用”，等待确认。
6. 点击“开始”，等待“已执行 START”，确认设备进入 `REPLAYING`。

课程交付版本地保留以下四个演示样例，来源与哈希见 [演示资产清单](../experiments/demo-assets.json)。2026-09-22 验收与 2026-10-17 复查时设备也提供这四个实例；使用时仍以设备实际下拉列表为准。

| 文件名 | 所属油井 | 数据实例类别 |
| --- | --- | --- |
| `WELL-00001_20170201010207.parquet` | WELL-00001 | Normal，正常 |
| `WELL-00001_20170320120025.parquet` | WELL-00001 | Severe Slugging，严重段塞流 |
| `WELL-00001_20170316110203.parquet` | WELL-00001 | Flow Instability，流动不稳定 |
| `WELL-00014_20160304155906.parquet` | WELL-00014 | Hydrate in Service Line，管线水合物 |

实例类别不表示文件的每个采样点都处于该异常，也不保证模型预测与标签一致。不要为获得预期报警而修改数据或结果。

### 3.2 开始、暂停、停止的区别

| 操作 | 作用 |
| --- | --- |
| 开始 | 启动已加载实例；处于暂停状态时继续回放 |
| 暂停 | 暂停发送数据，保留当前回放位置 |
| 停止 | 结束当前回放；再次开始将从文件开头读取 |
| 应用速度 | 设置 1×、5×、10×或 20×速度 |
| 加载实例 | 选择已有 Parquet 文件；应先停止回放 |

系统默认不自动开始回放。文件播放完毕后设备可保持在线，但曲线不会继续更新。演示结束时点击“停止”；如果临时改变速度，可恢复为原先值。

## 4. 七个页面的使用方法

### 4.1 总览

查看受监测油井数量、在线边缘设备数和待确认报警数。此页适合开场介绍；需要最新状态时刷新页面，不能把一直打开的旧数字当作持续更新的证据。

### 4.2 实时监测

选择与回放文件对应的井，例如回放 `WELL-00014_…` 时选择 `WELL-00014`。七条曲线对应 `P_PDG`、`P_TPT`、`T_TPT`、`P_MON_CKP`、`T_JUS_CKP`、`P_JUS_CKGL`、`QGL`。

讲解时可按压力、温度和气举流量相关变量分组，指出变化趋势和变量间的同步变化；变量的具体测点与单位应以数据集说明为准，不凭数值臆测。

页面同时显示活动推理类别、窗口状态、置信度和异常分数。模型需要约 180 秒的数据窗口，通常按 10 秒数据步长更新。在每秒一条的数据上，10×回放理论上约 18 秒送入首个窗口，实际耗时还受处理和网络影响。

观察要点：连接状态正常、曲线采样时间推进、完整窗口出现、推理结果持续更新。新一轮回放开始时可能暂时看到上次保存的结果，应结合“模型中心”或“辅助诊断”的窗口以及历史记录确认。

### 4.3 模型中心

页面上方展示模型加载状态、版本、训练数据版本、评估指标和离线 CPU 延迟。下方选择油井并点击“刷新”，查看同窗口对照。

- **XGBoost active**：当前活动模型，参与报警规则。
- **TCN shadow**：影子模型，只作对照，不改变报警状态。
- **置信度**：模型对当前窗口类别的评分，不是系统准确率。
- **Macro F1**：已保存评估结果中的类别平均指标，不代表当前现场或未见油井的可靠性。
- **窗口推理延迟**：当前结果的执行耗时；与上方离线评估延迟的测量条件不同。

两个模型结果不同是可以展示的实验现象，不要将 shadow 临时改成 active 来迎合预期。

### 4.4 报警中心

查看事件、油井、严重度、时间与状态，点击“刷新”获取最新记录。默认规则为连续两个 active 异常窗口触发报警，连续三个 Normal 窗口后标记恢复；TCN 不触发报警。

“确认”表示人工已经知悉，不能解释为异常已经消除。确认会保存状态，答辩时如要演示该操作，先讲解待确认记录，再点击一次。正在持续的同一异常不一定每次回放都产生新报警；已有未恢复事件可用于讲解，不能承诺每次启动立即新增一条。

### 4.5 辅助诊断

**查看已验证的 DeepSeek 报告：**

1. 进入“辅助诊断”，选择 `WELL-00014`，点击“刷新”。
2. 找到创建时间 `2026-09-22T09:28:31.184659Z` 的记录，即北京时间 17:28:31 生成的报告 31。
3. 核对请求 ID `3b8f386d-8dbc-4d03-9e61-b8b3117cc013`。报告分析的是 `2016-03-04 16:21:16–16:24:15 UTC` 窗口。页面不显示内部数字编号 31，因此用创建时间和请求 ID 定位。
4. 阅读分析与三个 References；无需点击“生成受控诊断”，也无需重新开始回放。

**为最新窗口生成新报告：**

1. 选择油井，点击“刷新”。
2. 查看只读输入区域中的 active 模型、版本和窗口，确认是准备分析的已保存结果。
3. 点击一次“生成受控诊断”，等待新记录出现在列表顶部。“生成中…”期间不重复操作；当前外部 HTTP 超时配置为 30 秒，整体页面耗时还包含取数与保存。
4. 依次查看监测摘要、模型证据、变量摘要、可能解释、人工核查建议、References 和限制说明。
5. 核对请求 ID、模型/知识库版本、证据状态和降级原因。

页面使用该井最新的 active 结果生成报告，不提供任意历史窗口选择器。旧报告会继续保留，升级系统不会自动把它们重写成新格式。

页面默认只列出最近 20 条诊断。报告 31 在 2026-10-17 复查时仍可直接看到；若以后被新记录挤出列表，不表示已删除。可使用预先留存的演示材料，或由维护人员通过只读历史接口查询（接口最多返回 100 条）；不要为找旧报告反复点击生成。

2026-10-17 只读复查时 DeepSeek V4.1 Flash 仍启用，API 标识为 `deepseek-flash`；本次本地整理不重新验证外部连接。XGBoost/TCN 负责窗口分类，DeepSeek 负责把已有证据组织成分析文字；它不替代分类模型，不更改报警。页面“模型 / 知识库”中的模型版本是 XGBoost 版本，不是 DeepSeek 名称。报告 31 的后台审计已确认 `deepseek / deepseek-flash / completed`。

新报告调用会向 DeepSeek 发送井和窗口标识、七变量统计、模型结果、报警摘要及引用元数据，可能产生 API 费用；不发送完整原始时序。查看或刷新已有报告不会重新调用模型。

当前知识检索是受审阅静态条目的轻量关键词匹配，不是任意文档上传、向量数据库或通用聊天机器人。系统根据实际检索结果生成引用；发给 DeepSeek 的是引用元数据，而非知识文档全文。

| 页面状态或内容 | 含义与讲解方式 |
| --- | --- |
| 报告 31：“安全降级”，原因仅为缺少同窗口 SHAP | DeepSeek 调用已成功；离线解释证据不齐全，不能声称已获得该窗口的 SHAP 特征贡献 |
| `LLM analysis unavailable` | 本条报告使用模板；可能是当时未启用 LLM，或发生超时、认证、限流、返回格式问题 |
| “拒答” | 置信度不足、结果不适用或缺少可引用资料等原因使系统拒绝分析，阅读具体理由 |

本版诊断中的模型证据标记为 `Experimental model output`，不能当成确定故障事实。LLM 不可用时监测和历史仍可使用；模板报告应明确介绍为模板。报告 30 是接入前保留的模板降级记录，可与报告 31 对照，不需要现场关闭生产 LLM。

### 4.6 历史事件

选择油井，按需填写开始时间、结束时间与模型类别，然后点击“查询”。每次最多显示 500 条，记录多时缩小时间范围。

上方是活动模型事件，下方是同时间范围的七变量记录。模型类别筛选作用于推理事件，不会把下方传感器表自动变成仅属于该类别的数据。历史页展示表格，七变量曲线位于“实时监测”。

数据原始时间来自多年以前；若结果为空，先清空时间和类别条件，再按已知采样时间查询。历史库可能包含多次回放结果，不应把混合记录直接当成一次连续现场采集。

同一文件多次回放会保存不同接收序列的记录。诊断窗口统计按井和采样时间读取，可能包含多次回放的同时间记录，因此报告中的样本数可能超过单个 180 秒窗口的采样数；不要将其介绍为已按回放批次隔离或去重的统计。

2026-09-22 彩排使用的查询示例：浏览器时区为中国标准时间时，选择 `WELL-00014`，开始时间填 `2016-03-05 00:00`，结束时间填 `2016-03-05 00:30`，模型类别选 `Hydrate in Service Line`。当次查询得到 141 条活动模型事件；后续回放后数量可能改变。其他时区应换算同一 UTC 区间 `2016-03-04 16:00–16:30`。

展示报告 31 时可说：“这是已保存的真实 DeepSeek 分析报告，依据指定窗口的统计和模型结果生成。页面提示安全降级，是因为缺少同窗口的离线 SHAP 解释。模型判断和文字分析都需人工核验。”若现场生成了新报告，应以该条实际状态为准；不要把已保存记录说成刚刚生成。

### 5.3 模型研究结论的正确讲法

> 当前运行链路使用四分类 XGBoost 和 TCN。后续单独研究的二分类 XGBoost 候选模型，在验证集表现较好，但在独立测试井 WELL-00014 上异常召回率约 2.49%、异常 F1 约 4.85%，跨井泛化没有达到要求。因此该候选模型被否决，从未部署，也没有用测试集继续调参。

该二分类研究与线上四分类模型不是同一个模型。不能把被否决候选模型的结果写成已上线能力，也不能用线上高置信度代替跨井泛化验证。

### 5.4 常见答辩问题

**是真实传感器采集吗？** 使用真实公开油井数据回放模拟采集；树莓派、MQTT、云端存储和网页链路实际运行，没有接入本项目的实体油井传感器。

**为什么需要边缘设备？** 它承担数据读取、协议转换、发送、状态上报和受控回放，使采集侧与云端分析解耦。

**为什么用两个模型？** 活动模型驱动现有报警逻辑，影子模型用于同窗口比较，便于评估新模型而不直接改变报警行为。

**不用大模型能工作吗？** 可以。监测、历史、模型推理和报警不依赖外部大模型，诊断可返回受约束模板。

**DeepSeek 在系统里做什么？** 它接收受限统计摘要、模型结果、报警摘要和引用元数据，生成辅助分析文字。窗口类别和报警仍由原有推理与规则链路决定。

**为什么调用成功还显示安全降级？** LLM 调用状态与证据完整程度不同。报告 31 的 DeepSeek 调用成功，但缺少同窗口 SHAP；系统因此保留证据不完整的提示。

**是否可以投入工业生产？** 当前成果是课程教学系统。模型泛化、长期稳定性、传感器接入及生产级安全治理还需要独立验证。

## 6. 现场问题处理

| 现象 | 优先检查与处理 |
| --- | --- |
| 网站无法打开 | 检查电脑网络与域名访问；使用已准备录像和截图，并说明当前无法连线 |
| 设备 OFFLINE | 检查树莓派电源、网络、VPN 和 MQTT；不要反复点击开始 |
| 命令已发送但未确认 | 等待页面回执；超时后刷新设备状态，确认连接，再决定是否重试 |
| 设备 ONLINE，但曲线不动 | 检查是否已开始、是否选错井、文件是否播放完毕 |
| 连接正常但仍无新推理 | 检查新遥测是否到达、180 秒窗口是否完整、模型是否 ready |
| 模型 unavailable | 检查部署制品和挂载，由维护人员处理；不要临时训练或替换模型 |
| 历史查不到数据 | 清空“今天”的筛选条件，按原始采样时间和浏览器时区查询 |
| 没有新报警 | 检查 active 结果、连续窗口条件和已有事件状态；可展示已有记录 |
| 显示“生成中…” | 等待当前请求完成；不要刷新后反复生成。外部 HTTP 超时配置为 30 秒，取数与保存也需时间 |
| 安全降级仅提示缺少 SHAP | 表示解释证据缺失；报告 31 已确认 LLM 成功，可直接用于讲解这一边界 |
| 新报告含 LLM analysis unavailable | 保留模板演示；维护人员检查密钥、余额、网络、限流或返回格式，不反复点击重试 |
| 拒答 | 阅读置信度、模型结果或引用证据不足的具体原因 |
| 报告仍是旧格式 | 检查创建时间；旧审计记录不会自动更新。可查看报告 31，需要新分析时再生成 |

## 7. 运行与部署说明（供接手者）

浏览器使用者无需安装开发依赖。需要独立部署时，应另外准备 Docker、PostgreSQL、MQTT/TLS 配置、合法取得的 Parquet 样例、已验证模型制品以及 Edge Agent 的网络和持久化配置。

云端 API 的目标为 Linux amd64 / Python 3.12，前端构建使用 Node.js 22。当前 API 依赖中的 PyTorch wheel 是 Linux x86_64 版本，Apple Silicon 默认原生构建不在已验收范围内；树莓派仅运行独立 Edge Agent。平台、证书、代理和启动顺序见 [部署说明](../../infra/README.md)，所需外置文件见 [根目录交付清单](../../README.md#外置数据模型与配置)。

源码仓库不包含真实 `.env`、证书私钥、完整数据集和模型二进制，不能仅复制示例配置就视为可直接运行。

独立搭建新环境时，维护人员完成配置后可在对应源码仓库根目录使用：

```bash
docker compose --env-file .env -f infra/docker-compose.yml up -d --build
```

`--env-file .env` 用于 Compose 变量替换。API 的容器环境文件路径、私网 MQTT 绑定地址、TLS 主机名和证书也必须正确。API 和 Web 默认只绑定服务器回环地址，公网入口由系统 Nginx 提供；不要为方便演示而开放数据库或公网 MQTT。

Compose 的 8085 端口仅提供静态页面，完整应用还需系统 Nginx 的 API/WebSocket 代理。开发时可在 API 能通过开发机 `localhost:8000` 访问的前提下，用 `apps/web` 的 `npm run dev` 启动自带代理的 Vite 页面，端口以终端输出为准。

现有生产环境采用版本化发布目录与镜像，上述命令不是本次生产升级步骤。维护现有实例应按当前发布记录操作，不要从服务器遗留旧源码直接重建。修改 LLM 环境文件后需要重建 API 容器以加载新变量，单纯 `docker restart` 不会更新容器环境。

树莓派使用 `services/edge-agent/docker-compose.yml` 及其独立 `.env`，数据目录只读挂载，序列状态持久化。已部署实例应按部署记录维护，不要未经核对直接重跑不同启动方式。

源码默认关闭 LLM；2026-09-22 的生产配置已启用 DeepSeek V4.1 Flash，2026-10-17 只读复查确认该配置仍在。独立部署时应由维护者配置 `DIAGNOSTIC_LLM_ENABLED`、`DIAGNOSTIC_LLM_PROVIDER`、`DIAGNOSTIC_LLM_BASE_URL`、`DIAGNOSTIC_LLM_API_KEY`、`DIAGNOSTIC_LLM_MODEL` 等环境变量，并单独验证外部服务。凭据不写入本文、源码、PPT 或截图。

DeepSeek 接入参数与历史验收模型标识见 [DeepSeek 接入说明](deepseek-setup.md)。精简后开发环境依赖需重新安装；本地只留四个演示样例和当前模型，完整训练数据需重新获取。
