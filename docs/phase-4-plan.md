# 第四阶段计划：可解释诊断与受控 RAG 辅助分析

## 目标

在第三阶段双模型对照稳定后，为 **已验证的 active/shadow 推理结果** 提供可追溯的解释和教学辅助诊断。第四阶段不改变报警来源，不连接现场控制，不把原始遥测直接交给大模型。

## 工作包

1. **XGBoost 可解释性**：离线生成全局特征重要性和窗口级 SHAP 摘要；制品带模型版本、特征 schema、窗口时间和免责声明。TCN 先展示概率、趋势与对照差异，不伪造 SHAP。
2. **知识库治理**：收集公开、可引用的 3W 数据说明、油井异常教学材料和项目运行手册；建立来源、版本、许可、分段与检索评估清单。敏感运行参数和凭据永不入库。
3. **受控 RAG 服务**：输入限定为模型结果、SHAP/趋势摘要和检索片段；输出必须包含引用、置信边界、缺失信息及“仅教学辅助，不构成操作指令”的提示。禁止给出控制命令。
4. **界面与审计**：新增诊断页，展示 active/shadow 对照、特征贡献、检索来源和生成记录；记录模型版本、文档版本和请求时间，便于答辩复现。
5. **评估与演示**：构造 Normal、三类目标异常及不确定案例；人工检查事实性、引用覆盖率、拒答行为和延迟。保留第三阶段的 XGBoost 报警回归测试。

## 验收与退出条件

- 每条诊断可追溯到同一窗口的模型结果与至少一个公开来源；无来源或低置信度时明确拒答或提示不确定。
- RAG 不读取原始完整时序，不发 MQTT 控制命令，不修改报警状态机。
- 在课程演示环境内，诊断页加载和响应时间满足可交互要求，并保留可复现的评估记录。
- 只有当 active XGBoost 与 TCN shadow 的指标、延迟和对照证据完整时，才开始第四阶段；TCN 仍不得自动升级为 active。
