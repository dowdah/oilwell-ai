# 第四阶段知识库治理与检索评估

`manifest.json` 是受控诊断的唯一知识来源。每个 `excerpt` 是一个经过审阅的检索分段，而不是网页或现场文档的镜像。运行时只检索这些分段和它们的元数据；每个分段保留 source title、source/version、source identifier 以及可得的 page/section。

## 入库门槛

- 仅收录公开、可访问且教学相关的资料；逐条记录 URL、版本、许可、标签和不超过必要范围的摘要。
- 不得收录完整原始遥测、油井标识关联表、现场设定值、操作规程、MQTT/数据库配置、证书或凭据。
- 资料、摘要和标签均需人工审阅；变更通过普通代码审查后才可部署。外部链接失效、许可不清或内容不可核验时删除条目。

## 检索评估清单

每次知识库变更，以 `Normal`、`Severe Slugging`、`Flow Instability`、`Hydrate in Service Line` 和未知/低置信度各运行一次：

1. 前四类至少返回一个语义相关、可打开且版本/许可齐全的来源；未知或低置信度结果必须拒答。
2. 检查诊断内容中的 `[source-id]` 与返回 `citations` 一一对应，且不把引用扩展为现场控制建议。
3. 记录命中来源、人工事实性判断、引用覆盖率和响应耗时到阶段演示手册；任何失败都不得放行新资料。

## Phase C LLM 边界

- OpenAI-compatible API 仅接收已压缩的窗口统计、实验性模型输出、报警摘要和本次实际检索到的分段；不接收完整原始时序。
- 返回文本必须使用不确定表述，不产生控制指令。References 由 retriever 返回集合确定，LLM 不能增加引用。
- API 未配置、不可用或返回不合约格式时，系统仍生成模板报告，并明确 `LLM analysis unavailable`。
